## Summary

Andy asked F2 to fix three findings from Ahmad Mesto's review and the stemmer. Section 5: wmtm dropped notes that shared words. Section 7: the context block showed attention, not evidence. Section 10: GoalChainer read none of the notes wmtm sent it, and tied goal candidates were broken by list order. All four are fixed on branch `hive/t-2026-11-06-wmtm-f2-context` (commit 6ce9286 for the code, base 77d62b9 = PR #9; main has not merged PR #9, so there was no rebase). Each fix has a test of the review's acceptance condition. Each test also has a negative control, which undoes that one fix and confirms the test then fails for the stated reason. All 13 new tests pass on the fix, and all 6 controls fail. The gates pass with P4's env: goal+PC 280/280 and the full suite 767 passed, 22 skipped. The goal+PC gate shows 280 rather than 285 because 6 tests of the removed v1 feed were deleted and 1 was added.

For section 10 I **removed the v1 path** rather than making GoalChainer read the notes. GoalChainer v1 accepts only `(Acceptable <action>)` STV/EC atoms for its fixed incident actions. To encode "rex is a dog" in that form, wmtm would have to invent truth values. `decide()` now returns a message explaining this, and the orchestrator's off-by-default `use_goalchainer` phase sends nothing. In v2, exact ties now reach GoalChainer v2 as ties. With the real v2 runtime, two equally urgent questions to Quill and Wren escalate to a human in both list orders, and nothing is proposed. Two behaviour changes need andy's attention before F3. (1) The context block now drops request-irrelevant filler even when it has high attention, because the relevance floor ignores attention. (2) A tie now stops the goal series, so nothing is proposed in that run. No live flag, `goal_prompt` or live wmtm was touched. Nothing was pushed or restarted.

## Limits and open points
- **Floor semantics (needs andy's OK before F3).** With a request known, notes with low or zero relevance are no longer let through by high STI. In `test_track_p`, 3 unrelated high-STI notes used to fill the remaining slots and are now dropped. Relevant notes with 0.7·rel < 0.2 survive only among the 5 pinned best matches.
- **Ties stop the goal series.** v2 reviews the series one proposal at a time, and the first review ends on `escalate`. Two equally urgent asks are now logged as an escalation and are not shown, where before both were proposed in list order. The A/B rerun (F3) should count escalations.
- **Parse equality is not wired into the turn path.** `same_proposition(parse_of=…)` supports it, but `context_for` merges only on identical normalised text, so it never merges distinct propositions. Reading the parse cache in the time-budgeted recall path was not measured.
- **Stemmer.** `needs.keys()` still ignores words under 4 letters. The stem fix lets "dogs" normalise to "dog", but a sentence's own "dog" is not a topic key, so the fix matters only where key sets carry the short form (anchors, the parser's queries).
- **Selection without attention.** Selection uses relevance and then age. With no request known and more than `context_max_items` notes, the newest are shown. The per-line character budget can still cut the attention-ordered tail if `context_total_chars / n < 250` (not reachable with the defaults: 6000/15).
